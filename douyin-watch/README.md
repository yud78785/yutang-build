# 鱼塘 · 抖音自主浏览（Windows 便携实验版）

目标：不用 Python、Node.js 或浏览器扩展，打开一个 EXE，让真实 Windows Edge 可见地播放抖音公开视频，读取能看见的标题/评论/已有 AI 总结，自动切换下一条，输出 CSV 证据，并在本机保存有限的真实播放器画面取样（不采集音频）。

## 1. 使用

1. Windows 10/11 需要已安装 **Microsoft Edge**，双击 `YuTangDouyinWatch.exe`。
2. 默认网址 `https://www.douyin.com/`，设置本次最多 1–50 条；点击 **打开 Edge 并开始**。
3. 如果页面需要登录或先打开视频，**只在弹出的 Edge 手动操作**。不要把密码、短信验证码发送给程序。
4. 程序查看实际活动 `<video>` 播放进度，不会强制重置已在播放的视频；如果从中途开始，会等待自然循环后观察到接近开头至至少 85% 的进度，再判断完整播放。标题、网页地址或媒体加载状态单独变化不再算换视频；只有媒体变化有交叉证据才判定新视频。默认在 10%/50%/85% 附近保存最多三张本地画面取样，再读取本条可见评论及网页已有 AI 总结。若未完成，不自动跳到下一条。
5. 随时点 **停止并关闭本次 Edge**。关闭程序窗口时会先等待本次 Edge 完成清理。点 **打开观看记录** 可查看 UTF-8 CSV 和每次会话独立的 `DouyinWatch-...-frames/` 文件夹；每条最多三张，跨会话不会覆盖。CSV 对网页文本文字进行表格公式防护。

## 2. 明确边界

- 实现的是 **本地只读自动浏览控制器**，不是视觉/语音大模型。能保存实际视频区域的 **PNG 画面证据**，但**不能自动解释画面、录制/听懂声音，也不能自行生成 AI 总结**。CSV 的 `audio_status` 只反映视频播放器是否静音，**不是声音已经被听到或理解的证据**。只有网页已显示 AI 总结时，才读取现成内容。拿不到的内容标为空，绝不填造。
- 不绕过抖音风控、验证码、地理限制或登录要求；不请求任何私有接口，不抓取/传播账号 Cookie。
- 不点赞、收藏、评论、关注、私信、转发，不上传记录到服务端。
- 由于抖音网页是不断变化的单页应用，选择器可能失效；无法确认新视频就停止，不能视为实战验收通过。
- Edge 使用 `%LOCALAPPDATA%\YuTangDouyinWatch\edge-profile` 独立资料目录；CSV 仅保存在 `%LOCALAPPDATA%\YuTangDouyinWatch`。
- 当前为**未签名实验候选**，不是正式发布版本，不要忽略 Windows 安全警告强行运行。2026-11-17 Actions #44135162273 已通过**旧源码** Windows 离线 Edge 测试与打包，本分支新增的画面与退出清理改动**尚未运行 Windows CI，更没有抖音现场 PASS**。

## 3. 开发 / 验证

```
python -m pip install -r requirements-win.txt
python -m unittest discover -s tests -v
python app.py --self-test
python app.py
```

Windows 单文件构建（仅隔离实验分支的 GitHub Actions 一次性构建）：

```
pyinstaller --noconfirm --clean --onefile --windowed --name YuTangDouyinWatch --collect-all playwright app.py
```

下载 CI ZIP 后 EXE 的 `--self-test` 必须 PASS 才算包装成功。**云端 Windows 构建成功不代表真实抖音播放通过**；真实功能需要用户电脑上的 Edge 现场验证。

源码参考：抖音帮助页 `https://www.douyin.com/help` 对 ↓ 切视频的说明；只读检测优先使用 `[data-e2e="feed-active-video"]` 和真正活动的 `<video>`。零调用外部大模型；不需要提供 API Key。


## v2 证据化观看模式

- GUI 默认选择「验证预览」：必须在同一视频上观察到至少两次有效媒体时间前进、累计至少 8 秒，才能记录 `PREVIEW_VERIFIED`；这不是“完整看完”。
- 「完整观看」为单独模式，必须观察媒体时钟持续推进至接近结尾（不得把等待、跳播或首尾误配算成看完）。
- `watched_s` 改为媒体进度的保守累计，不再是后台等待的秒数。长视频例如 2267 秒不需要先等到结束才取得预览、评论或下一条。
- 每轮结束保留专用 Edge 供用户检查；由「停止并关闭本次 Edge」主动关闭。所有互动默认关闭，仍不包括大模型音视频理解。
- 新分支必须重新完成 Windows 打包和现场抖音联网验收；旧候选不能算新版本通过。


## v3 现场诊断与标签页接管

- 若用户在独立 Edge 中新开抖音视频标签页，程序会优先识别最新的、可见的抖音视频，不再只守着初始首页。只读取非抖音标签页的 URL 元数据用于域名排除，**不读取站外页面 DOM**。
- 增加「现场诊断」入口。每次会话在本机生成独立的 `DouyinWatch-...-diagnostics.json`，最多记录最近 64 个播放器时间和播放/缓冲状态，以及最多 50 条结果码。成功与失败都可核验；不会自动上传。
- 诊断严格排除页面正文、评论、标题、密码、Cookie、完整 URL、CDN 地址、截图和浏览器存储信息。只有时间、播放/网络状态与合法数字视频 ID。
- **新提交必须重新验收 Windows EXE**；旧 v2 的 29/29 通过结果仅属于旧 SHA，不视为当前版本通过。真实抖音联网播放和 AI 音视频理解仍是独立待验项。


## v4 标签页接续（独立实验分支）

- 每轮完成后，优先接续专用 Edge 中用户新开的**另一条已确认的抖音视频**；否则沿用原有的 ↓ 键等有限切换方式。严禁把同一视频 CDN 资源变化当成下一条。
- 上一条播放失败时仍写入失败的 CSV/诊断结果；**只有用户已打开另一条确实不同的视频标签页**，才接续下一条，不无限重试、也不将失败记为成功。
- 跳转前只用域名白名单筛选：站外标签页不执行 DOM、截图或脚本检查。
- 这是 v4 源码更改，v3 的 Windows 通过记录不可直接沿用，仍须独立 Windows EXE 与真实抖音现场验收。


## 云端 Windows 真实抖音网站一次性探针

- 新候选增加显式命令行 `--live-probe --probe-json live-douyin-probe.json`，只用于一次性受控验收，正常双击仍打开 GUI。
- 与独立资料目录隔离，访问真实 `https://www.douyin.com/`，使用生产的 BrowserWatcher 只观察最多一条公开视频：可见视频、实际媒体前进及只读评论数量。每条最多 25 秒，首次找视频最多 18 秒；若网络、登录或风控阻止，按未通过证据报告，不尝试绕过。
- 打包的 EXE 在 Windows 2022 执行真实网站探针；结果为有限字段的本地 JSON，不含 Cookie、账号、网页文本、标题、评论正文或真实用户资料，临时 Edge profile/CSV 在退出后删除。
- 此探针使用 CI 的无头 Edge（headless Edge），**不能代表用户本机的可见 Edge 启动、真实评论、音画理解已经通过**。本机仍需单独实测。


## 现场诊断改进（候选修复，需独立 Windows 验收）

- 专用 Edge 启动前就创建本地脱敏诊断文件；找不到可见视频时每约 6 秒更新一次，视频正在播放时也周期性保存。点击停止前即可查看，程序正常退出后仍有最终回执。
- 诊断新增网站 HTTP 响应码、页面加载状态、网页包含的视频元素总数/可见数量、是否出现登录提示（布尔值）、暂停、缓冲、播放器时间；**不会记录 Cookie、标题、页面文本、视频 ID 到复制内容，也不会上传任何数据**。
- GUI 新增「复制脱敏诊断」，点击后把受控字段和**当前实际 EXE 的 SHA-256**复制到剪贴板，可直接粘贴聊天。只读且不自动发送，原始诊断仍保存在本机。
- 该修复旨在获取真实 Windows 现场失败信息，不证明抖音真实播放已经通过；上轮云端探针仍是 HTTP 200 / 无可见视频。
